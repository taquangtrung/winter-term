en-us.aff/en-us.dic and en-gb.aff/en-gb.dic are the Hunspell dictionary files
from the npm packages `dictionary-en` (v4.0.0) and `dictionary-en-gb` (v3.0.0)
respectively (github.com/wooorm/dictionaries), copied here as static assets -
not an npm dependency - since neither package is safely bundleable through
this project's esbuild config (their own loader does a top-level-await
fs.readFile relative to the package's own install location, which doesn't
resolve correctly once bundled into dist/extension.js). dictionary.ts parses
these two files itself; see its file header for why that's a hand-written
parser rather than a Hunspell library like nspell.

Both .aff/.dic file pairs have manual patches on top of the unmodified
upstream data (see git history for src/spell/data for exact diffs). If
re-syncing from a newer dictionary-en/dictionary-en-gb release, reapply
these, and check whether the newer release already fixed them upstream:

  - `audit` is missing the `B` (SFX -able) flag, so "auditable" was flagged
    as a misspelling despite being a real word (audit/GMDS -> audit/GMDSB).
  - No suffix rule derives an -ity/-ability form from anything, so
    "auditability" was also missing. Added a new SFX Q rule to both .aff
    files, mirroring SFX B's own [^aeiou]/ee/[^aeiou]e conditions but with
    "ability" instead of "able" - English's -able/-ability alternation is
    its own irregular pattern (capable -> capability, not capableity via a
    second suffix chained onto -able), not something continuation classes
    would help with even if this .aff format used them (it doesn't - see
    dictionary.ts's file header). `audit` was flagged with Q too
    (audit/GMDSB -> audit/GMDSBQ), superseding an earlier version of this
    patch that added "auditability" as its own standalone stem - the new
    SFX Q rule is reusable for any future word with the same gap, whereas a
    standalone stem only ever fixes that one word.
  - `link` is missing the `B` (-able), `Q` (-ability), and `U` (PFX un-)
    flags, so "linkable"/"linkability"/"unlinkable"/"unlinkability" (common
    terms in privacy/blockchain writing) were all flagged as misspellings
    despite the underlying rules already existing (link/MDRSG ->
    link/MDRSGBQU).
  - "review" was missing entirely (not even the base word), added as
    review/MDRSZGB (mirrors preview/MDRSZG's flag set, plus `B` for
    "reviewable"). `verify` was missing the `R` (-er/-ier) flag, added for
    "verifier" (verify/DSNG -> verify/DSNGR). "subcommand" was missing -
    added as its own standalone stem (subcommand/SM), matching how every
    other sub- word here is already a standalone entry rather than a
    productive PFX rule (subcategory, subclass, subcommittee, ... - not
    every English noun productively takes "sub-", unlike "re-"/"un-").
  - "anonymize"/"anonymization" were both missing (only "anonymous"
    existed). Added as their own standalone stems (anonymize/DRSZG,
    anonymization/M), matching how "-ize"/"-ization" pairs are handled
    everywhere else here (e.g. modernize/DRSZG + modernization/M,
    organize/AESDG + organization/ASM) - "-ization" is never derived from
    the "-ize" verb via a suffix rule in this dictionary.

upstream project the previous flat-file version of this dictionary (see git
history) was already sourced from, just via SCOWL's own Hunspell-format
release instead of Debian's `wamerican`/`wbritish` packages. The word list
